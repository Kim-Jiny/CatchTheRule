# 암호 해독(cipher) · 저울 추리(scale) 모드 명세

생성기(Python) / iOS(Swift) / Android(Kotlin)가 **같은 규칙**을 쓰도록 정의한 단일 명세. 홈 허브·해금 게이트·캠페인 흐름·타임어택 믹스·진행도 저장은 기존 모드(`fragment`, `target`, `match`)와 **완전히 같은 방식**으로 붙인다. 변경 지점 체크리스트 = `git show ee9a536 --stat`(조각 숫자 모드 추가 커밋)의 파일 목록. 참고 명세: `docs/fragment-mode-spec.md`.

공통:
- 둘 다 **키패드 직접 입력 전용**(`inputType:"keypad"`, `choices:null`). 정답은 숫자 문자열, 최대 4자리(앱 입력 제한 `typed.count < 4`와 호환 → **answer 는 1~4자리, 선행 0 없음. 단 cipher 의 map/rev 류에서 선행 0 은 허용하지 않는다**).
- 글자(번역 필요) 없이 **이모지 + 숫자**만 쓰는 언어 중립 퍼즐. 번역이 필요한 건 프롬프트/모드명/챕터명(l10n 완료)과 `hints`/`explanation`(7개 언어: ko,en,ja,zh,es,fr,de)뿐.
- 각 모드 14챕터 × 6문제 = 84문제. id `cpN_sMM`(cipher) / `scN_sMM`(scale). 챕터 안 order 1→6 점점 어려워짐.
- 모드 키·색·아이콘: cipher = `cipher`, 색 **#2DD4BF(틸)**, iOS 아이콘 `lock.open.fill`, Android `Icons.Filled.LockOpen`. scale = `scale`, 색 **#E879F9(퓨샤)**, iOS 아이콘 `scalemass.fill`, Android `Icons.Filled.Balance`(없으면 `Icons.Filled.Scale`/`Icons.Filled.Tune` 등 가능한 것). `PuzzleStore.trackOrder` 는 `[..., "fragment", "cipher", "scale"]` (8→9개; 홀수 → 마지막 카드는 가로 꽉 — 기존 로직 그대로 동작).
- l10n 키(이미 `gen_l10n.py` 에 추가됨, **UI 쪽에서 새로 만들지 말 것**): `mode_cipher`, `cipher_prompt`, `cipher_chapter_1..14`, `mode_scale`, `scale_prompt`, `scale_chapter_1..14`. 힌트/해설 UI 는 기존 재사용.
- 타임어택 믹스에도 포함(앞쪽 절반 챕터 규칙 그대로): 별도 UI 없이 기존 숫자 문제 경로(`SequenceDisplay`/ Android `PlayComponents`)가 각 디스플레이를 그리고, 프롬프트는 `cipher_prompt`/`scale_prompt`.

## 1. 데이터 스키마 (shared/content/puzzles.json 항목)

```
// cipher
{"id":"cp5_s03","type":"cipher","track":"cipher","chapter":5,"order":3,
 "pairs":[ [["🍎","🍌"],["7","3"]], [["🍌","🍇"],["3","9"]], [["🍇","🍎"],["9","7"]] ],  // pairs[i] = [입력 토큰들, 출력 토큰들]
 "query":["🍌","🍎","🍇"],            // 풀어야 할 입력 토큰들
 "answer":"379", "inputType":"keypad","choices":null,
 "hints":{ko:[3개],...7개 언어}, "explanation":{ko:"...",...7개 언어}}

// scale
{"id":"sc5_s03","type":"scale","track":"scale","chapter":5,"order":3,
 "scales":[ [["🍎","🍎"],["🍌","6"]], [["🍌"],["🍇","🍇"]] ],   // scales[i] = [왼쪽 접시 토큰들, 오른쪽 접시 토큰들] (양쪽 무게가 같다)
 "query":["🍎","🍇"],                 // 이 접시의 총 무게는?
 "answer":"9", ...}
```
- 토큰은 문자열. 이모지 토큰 = 미지수, **숫자 토큰("6","12")** = 고정 무게(추). cipher 의 출력 토큰은 숫자 문자열("7","12")이며 화면에서는 **이어 붙여 표시**한다(`["1","2"]`→"12"; 한 토큰이 "12"여도 이어 붙임 결과가 같도록 생성기는 **출력 토큰을 한 자리씩** 쪼개서 낸다).
- 앱 모델(Puzzle): `pairs: [[[String]]]?`, `scales: [[[String]]]?`, `query: [String]?`. `isCipher = pairs 비어있지 않음`, `isScale = scales 비어있지 않음`. Swift/Kotlin 모두 Codable/Serializable 로 디코딩(기존 optional 필드 방식).
- 이모지 풀(생성기, 시각적으로 구분 쉬운 것만): 🍎🍌🍇🍒🍋🍓🥝🍑🌙⭐🔥💧🌿🔔🎈🐟🐱🐸🚗🎲. 한 퍼즐에 쓰는 기호는 서로 달라야 한다.

## 2. cipher — 암호 해독
규칙(기호 → 값 `v(s)`, 퍼즐마다 기호별 값은 무작위 **서로 다른** 정수. rule 별 범위는 아래). 예시들로부터 값을 알아내 `query` 의 출력을 계산해 입력한다. **query 에 나오는 모든 기호는 예시에서 값이 (유일하게) 결정되어야 한다.**

| rule | 출력 계산 | 값 범위 |
|---|---|---|
| `map` | 각 기호의 값을 **이어 붙임** (값 한 자리 0~9) | 1~9 (첫 자리 0 금지) |
| `rev` | 이어 붙인 뒤 **뒤집음** | 1~9 |
| `sum` | 기호 값의 **합** | 1~9 |
| `diff` | 첫 기호 값 − 나머지 기호 값의 합(항상 양수) | 1~12 |
| `prod` | 기호 값의 **곱** | 1~9 |
| `wsum` | 위치 가중합 Σ i·v(sᵢ) (i=1,2,3…) | 1~9 |
| `cnt` | 합 + 기호 개수 | 1~9 |
| `dsum` | map 으로 이어 붙인 수 **+ 그 수를 뒤집은 수** (예: "73" → 73+37=110) | 1~9 |
- 한 퍼즐은 하나의 rule 만 쓴다. 입력 길이 1~4. **같은 기호가 입력에서 반복**될 수 있다(챕터 5+ 권장).
- 예시 수 3~6. 가능한 한 **예시가 "정확히 필요한 만큼만"** 주어져 유일해가 되게(검증기가 확인).
- **유일성 검증(필수)**: 검증기는 해당 rule 에 대해 기호 값 할당을 전수 탐색(값 범위 내, 서로 다름)해 **모든 예시와 일치하는 할당들에서 query 결과가 동일**함을 보장해야 한다. 또한 다른 rule(`map`,`rev`,`sum`)로 해석해도 예시와 모두 일치하는데 query 결과가 다른 경우는 **허용하지 않는다**(모호함 방지; 단 모든 rule 이 같은 답이면 OK).
- 정답 4자리 초과/0 이하 금지.

### 난이도 사다리 (챕터 → rule · 입력길이 · 기호 수)
| 챕터 | rule | query 길이 | 기호 수 | 비고 |
|---|---|---|---|---|
| 1~2 | map | 2~3 | 3 | 예시로 기호 각각이 드러남 |
| 3~4 | map→rev(3~4챕터 중 rev 섞기) | 3 | 4 | 순서 바뀐 query |
| 5~6 | sum | 2~3 | 3~4 | 예시 3~4개 연립 |
| 7~8 | diff, prod | 2~3 | 4 | |
| 9~10 | wsum, cnt | 3 | 4~5 | 반복 기호 |
| 11~12 | dsum, prod+반복 | 3~4 | 5 | |
| 13~14 | 위 rule 전부 혼합, 예시 입력 길이도 다양 | 4 | 5~6 | 정답 3~4자리 |

힌트 3개: ① rule 요령(예: "기호 하나하나가 어떤 숫자인지부터 찾으세요 / 숫자들을 더한 값이에요 / 순서가 뒤집혀요 …") ② 구체 단서(기호 하나의 값: "🍎는 7이에요" 형태, 언어 중립 부분은 이모지+숫자) ③ 결과의 자릿수나 첫 자리("답은 N자리 수예요"). `explanation`: 값 표 요약(예: "🍎=7, 🍌=3, 🍇=9 → 379") 언어 중립 문자열을 7개 언어에 동일하게 넣어도 된다.

## 3. scale — 저울 추리
각 이모지는 **양의 정수 무게**(서로 같을 수도 있음 허용 안 함: 퍼즐 안에서 서로 다른 값). 접시 한 쪽에 같은 기호가 여러 개 올라갈 수 있고, 숫자 토큰은 그 값만큼의 추. 각 저울은 **양쪽 총 무게가 같다**. `query` 접시의 총 무게를 구한다.
- 무게 범위: 이모지 1~12 (ch11+ 는 1~20), 숫자 토큰 1~20. 한 접시 토큰 수 1~5, 한 저울 양쪽 합쳐 2~8토큰. 저울 수 2~5, 미지수 2~5개.
- **유일성 검증(필수)**: 검증기는 미지수 무게를 범위 내 전수/제약 탐색해 모든 저울을 만족하는 할당을 모은 뒤 **query 총 무게가 단 하나**임을 확인한다(각 미지수 값 자체는 유일하지 않아도 되지만 query 값은 유일). 모든 미지수가 query 또는 어떤 저울에 반드시 쓰여야 하며, 저울이 불필요하게 중복(같은 식 두 번)이면 안 된다.
- 한쪽 접시가 비거나, 양쪽이 완전히 같은 토큰 구성이면 금지(자명). 같은 기호가 양쪽에 같은 개수 있으면 상쇄해서 저울 정규화 후 자명하지 않게.
- 정답 1~999.

### 난이도 사다리
| 챕터 | 미지수 | 저울 수 | 구조 |
|---|---|---|---|
| 1~2 | 2 | 2 | `🍎🍎=6`, `🍎+🍌=…` 처럼 한쪽이 숫자 추. query 는 단일 기호 또는 2토큰 |
| 3~4 | 3 | 3 | 연쇄 대입(🍎→🍌→🍇) |
| 5~6 | 3 | 3 | 양쪽에 기호가 섞임(🍎🍌=🍇🍇) |
| 7~8 | 4 | 3~4 | 상쇄해야 풀림(양쪽 공통 기호 소거) |
| 9~10 | 4 | 4 | 배수(🍎×3 …), query 3~4토큰 |
| 11~12 | 5 | 4~5 | 큰 무게(~20), 숫자 추 섞임 |
| 13~14 | 5 | 5 | 모든 기법 혼합, 정답 2~3자리 |

힌트 3개: ① 요령("한 저울을 다른 저울에 대입해 보세요 / 양쪽에 같은 것을 빼 보세요") ② 구체 단서("🍎 하나의 무게는 N이에요", N 은 실제 값 중 하나) ③ "답은 N 이하/자릿수". `explanation`: 값 표 + 계산(언어 중립 문자열 예: "🍎=3, 🍌=4 → 3+4=7").

## 4. 화면/조작 (앱)

### cipher
- 상단 프롬프트 `cipher_prompt`(기존 `fragment_prompt` 와 같은 스타일). 그 아래 **디스플레이 카드**(`CipherDisplay`): 세로 목록. 각 예시 행 = `[입력 이모지들 (큰 글씨)]  →  [출력 숫자 (모노스페이스, 모드색)]` 를 좌우 가운데 정렬로. 마지막 행은 `[query 이모지들]  →  [입력값 or "?"]` — 입력 중인 숫자를 모드색 큰 글씨로 보여주고, 비었으면 `?`(깜빡임 불필요), 오답이면 기존 흔들림/빨강 처리와 동일. 행 간격 균일, 예시 행은 약간 흐리게(textSecondary), query 행은 강조(모드색 테두리 카드 + 글로우).
- 이모지는 시스템 이모지 폰트 그대로. 행 수가 최대 7(예시 6 + query)이라 화면이 좁으면 스크롤(기존 세션 뷰의 ScrollView/GeometryReader 구조 활용).
### scale
- 상단 프롬프트 `scale_prompt`. 디스플레이 카드(`ScaleDisplay`): 저울 목록(세로). 각 저울 = **가로 평형 저울 그림**: 가운데 받침대, 수평 빔, 양 끝에 접시(둥근 사각 카드)에 토큰들을 가로로 나열(줄바꿈 허용), 숫자 토큰은 **회색 둥근 추 아이콘 + 숫자**(예: 원형 배지), 이모지는 그대로. 빔은 항상 수평(균형). 마지막에 `query` 접시를 모드색 강조 카드로 `[토큰들] = ?` (입력 중이면 `?` 자리에 입력값 표시).
- 토큰 크기: 이모지 28pt, 추 배지 24pt 지름. 접시 한 쪽 토큰이 많으면 두 줄로 줄바꿈.
- 정답/오답/입력 처리는 기존 공통 경로(키패드, 별, 광고, advance)를 그대로 재사용.
- 접근성: 각 디스플레이에 간단한 accessibilityLabel(iOS)/contentDescription(Android) — 예시 행을 "A B → 37" 형태 문자열로.

## 5. 테스트 벡터 (생성기가 만든다)
`scripts/cipher_test_vectors.json`, `scripts/scale_test_vectors.json`: `{"format":..., "eval_cases":[...], "samples":[실제 퍼즐 10개 요약]}`. cipher 는 `{"rule","values":{"🍎":7},"input":[...],"output":"37"}`, scale 은 `{"weights":{"🍎":3},"left":[...],"right":[...],"balanced":true}` 형태로 규칙 평가를 검증할 수 있게. 앱은 이 벡터로 파싱/디스플레이를 검증하면 되고, 별도의 규칙 평가 로직은 앱에 필요 없다(정답은 JSON 의 `answer`).

## 6. 파일 이름 규칙
- 생성기: `scripts/gen_cipher_puzzles.py`, `scripts/gen_scale_puzzles.py` (시드 고정, `shared/content/puzzles.json` 에 **해당 track 항목만 교체하는 멱등 병합**; 기존 다른 모드는 건드리지 않음). 검증기: `scripts/verify_cipher_puzzles.py`, `scripts/verify_scale_puzzles.py` (§2/§3 유일성 포함 전부 검사, 실패 시 비-0 종료). 기존 `gen_fragment_puzzles.py`/`verify_fragment_puzzles.py` 구조를 따른다.
- iOS: `Features/Play/CipherDisplay.swift`, `ScaleDisplay.swift`. Android: `ui/play/CipherDisplay.kt`, `ScaleDisplay.kt`.
