# 성냥개비 퍼즐 모드 (track: "match") 명세

세 구현(콘텐츠 생성기 Python / iOS Swift / Android Kotlin)이 **동일한 규칙**을 쓰도록 정의한 단일 명세.
숫자 만들기(track "target") 모드와 같은 해금 게이트·홈 허브·캠페인 흐름을 재사용한다. 참고: 메모리 `catchtherule-target-track`.

## 1. 게임
`6+4=4` 처럼 **틀린** 성냥개비 식이 주어진다. 성냥개비를 **드래그로 옮겨서**(정해진 `moves` 개 이내) 식을 **수학적으로 참**으로 만든다. 답은 하나가 아니어도 되며, 규칙을 만족하는 참인 식이면 모두 정답이다. 제출은 `확인` 버튼.

## 2. 데이터 스키마 (shared/content/puzzles.json 항목)
```
{"id":"mt1_s01","type":"match","track":"match","chapter":1,"order":1,
 "equation":["6","+","4","=","4"],   // 셀 배열(문자 하나가 셀 하나). 숫자는 한 자리씩 셀, 연산자 "+" "-" "=" (ASCII)
 "moves":1,                          // 허용 이동 개수(순변위 상한)
 "answer":"6+4=10",                  // 설계된 해(문자열). 정답 판정은 수학적 검증이며, 제출 시 answer 와 비교하기 위해 쓰는 대표값
 "inputType":"choices","choices":null,
 "hints":{ko:[3],en:[3],ja:[3],zh:[3],es:[3],fr:[3],de:[3]},
 "explanation":{ko:"...",...7개 언어}}
```
- 셀 개수 최대 8. `equation` 은 "참이 아닌 식"이며 모든 셀이 유효 글리프여야 한다.
- 앱 모델 필드: `equation: [String]?`, `moves: Int?`, `isMatch = equation 비어있지 않음`.
- 화면에 표시할 때 `-` 는 `−`(U+2212)로 그려도 되고 성냥개비 모양으로 그리므로 문자는 쓰지 않는다.

## 3. 셀과 슬롯 (논리 모델 — 세 구현 동일)
각 셀은 **슬롯 집합**(막대가 있으면 true)이다. 이동은 한 막대를 어느 셀의 비어 있는 슬롯에 옮기는 것(같은 셀 안 포함).

### 숫자 셀 — 7 슬롯 a b c d e f g
```
 aaa
f   b
 ggg
e   c
 ddd
```
a=위 가로, b=오른쪽 위 세로, c=오른쪽 아래 세로, d=아래 가로, e=왼쪽 아래 세로, f=왼쪽 위 세로, g=가운데 가로.
유효 숫자 패턴(슬롯 집합 → 숫자):
`0:abcdef  1:bc  2:abdeg  3:abcdg  4:bcfg  5:acdfg  6:acdefg  7:abc  8:abcdefg  9:abcdfg`
이 외의 집합은 **무효 글리프**.

### 연산자 셀 — 3 슬롯 hu hl v
hu=위쪽(중앙 약간 위) 가로, hl=아래쪽(중앙 약간 아래) 가로, v=중앙 세로. 두 가로 막대는 중앙에서 아주 가깝게(`=` 모양으로 보이게) 배치한다.
유효 패턴:
`"=" : {hu,hl}`   `"-" : {hu} 또는 {hl}`   `"+" : {hu,v} 또는 {hl,v}`
그 외({v} 단독, {hu,hl,v}, 공집합 등)는 무효.
어떤 셀이든 숫자 셀↔연산자 셀로 바뀌지 않는다(셀 종류는 고정; 연산자 셀은 `+ - =` 사이만 변환 가능, 숫자 셀은 숫자 사이만).

## 4. 식 판정
모든 셀이 유효 글리프일 때만 판정한다(아니면 "무효 식" → `match_invalid` 메시지 + 흔들림, 제출 안 함).
문자열로 이어 붙인 뒤: `=` 가 **정확히 하나**, 양변이 비어 있지 않고, 각 변은 `숫자 (+|-) 숫자 …` 형태(연산자는 숫자 사이에만, 맨 앞/맨 뒤 연산자 불가, 연산자 연속 불가), 각 숫자는 선행 0 불가(단 "0" 한 자리는 가능). 양변을 정수로 계산해 **같으면 참**. 음수 중간/결과도 정수로 허용(계산은 일반 정수 연산).

## 5. 이동 규칙/제약
- 막대 총 개수는 보존된다(옮길 뿐 추가/삭제 없음).
- `moves` = 허용 **순변위**: 현재 막대가 놓인 슬롯 중 **초기 상태에 없던 슬롯의 개수**가 `moves` 이하여야 한다. 드롭 시 이 값이 `moves` 를 넘으면 드롭을 거부(원위치, 흔들림 + `match_limit` 메시지). 같은 막대를 여러 번 옮기거나 되돌려도 순변위로 계산된다.
- 확인 가능 조건: 순변위 ≥ 1 이고 들고 있는 막대 없음. 순변위 0 이면 확인 비활성.
- 확인: 무효 글리프가 있으면 `match_invalid`(제출 안 함). 유효하고 식이 참이면 정답 → 기존 `submit(value = puzzle.answer)` 경로(정답 배지, 별, 지연 후 advance, 전면광고). 유효하지만 거짓이면 오답 경로(기존 오답 피드백/광고 로직, 상태 유지: 오답 값으로는 answer 와 절대 같지 않은 문자열, 예: "x"+현재식).

## 6. 조작(드래그)
- 식 영역에서 **막대를 직접 손가락으로 드래그**한다. 드래그 시작 지점 가까이(허용 반경 내)에 놓인 막대가 있으면 그 막대를 집는다(원래 슬롯은 비워지고 막대는 손가락을 따라간다).
- 집은 동안 **놓을 수 있는 빈 슬롯**(모든 셀의 비어 있는 슬롯, 방금 집은 막대의 원래 슬롯 포함)을 흐린 "고스트 막대"로 표시하고, 손가락에 가장 가까운(임계 거리 내) 고스트를 하이라이트한다.
- 손가락을 떼면 하이라이트된 슬롯에 놓고, 없으면 원래 슬롯으로 돌아간다.
- 순변위가 상한을 넘는 드롭은 거부(§5).
- 보조 버튼: `match_undo`(마지막 드롭 취소, 스택), `match_reset`(초기 상태로), `match_check`(§5). 상단에 `match_moves` ("이동 n / m", n=순변위, m=moves) 표시. 무효 글리프 셀은 은은한 붉은 톤으로 표시(정답을 알려 주지 않음).
- 작은 화면(8셀)에서도 한 줄에 들어가도록 셀 폭을 화면에 맞춰 조정. 막대는 둥근 모서리의 성냥(머리 쪽이 붉은) 느낌 또는 단색 막대, 다크 UI 에 맞게.

## 7. 힌트(3개, 7개 언어)·설명
셀 번호는 1부터. 해(solution)의 이동들을 기준으로 생성기가 만든다.
1) 막대를 **빼야 하는 곳**(해에서 막대가 사라지는 셀들): "N번째 기호에서 막대를 빼야 해요"
2) 막대를 **놓아야 하는 곳**(막대가 생기는 셀들), 같은 셀 안 이동이면 "같은 기호 안에서 옮겨요" 포함
3) 완성된 식 전체("정답 식: 6+4=10")
`explanation` 은 언어 중립: `6+4=4 → 6+4=10` 형태(연산자는 + − =).

## 8. 난이도 사다리 (14챕터 × 6문제, id `mtN_sMM`)
- ch1~8: moves=1, ch9~14: moves=2.
- 셀 수: ch1~2 = 5(예 `a±b=c`), ch3~4 = 5~6, ch5~6 = 6~7(두 자리 수 포함), ch7~8 = 7~8, ch9~11 = 6~8, ch12~14 = 7~8.
- 난이도 지표(생성기가 계산해 필터): 해의 개수(적을수록 어려움; ch12~14는 유일해 위주), 필요한 이동 유형(같은 셀 안 이동 → 다른 셀로 이동 → 연산자 셀이 연루 → 두 막대가 서로 다른 셀 쌍), 결과 숫자 크기. moves=2 챕터는 **1개 이동만으로는 풀 수 없어야** 한다. 모든 문제는 초기 식이 거짓이고 `moves` 이내의 이동으로 참이 되는 해가 최소 하나 존재.
- 중복 금지(equation 완전 일치 금지), 챕터 내 order 1→6 점점 어렵게.

## 9. 테스트 벡터
`scripts/match_test_vectors.json` — 생성기가 만든다. `{"eval":[{"cells":[슬롯집합문자열...],"valid":bool,"text":"...","truth":bool|null}], "moves":[{"equation":[...],"moves":k,"solution":"...","ok":true}]}` 형태로, 플랫폼 구현이 글리프 해석·식 판정·순변위 계산을 단위 검증하는 데 쓴다(슬롯 집합은 `abcdefg`/`hu hl v` 문자열).
